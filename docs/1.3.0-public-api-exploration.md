## 0. 结论速览 / TL;DR

1. **1.3.0 的对外 API = 两大件**：**自定义节点**（第三方注册节点类型，自己写求值逻辑）+ **宿主套件**（第三方方块成为图宿主，玩家用本模组编辑器直接编它的图）。
2. **值交换主路径 = 节点直连提供者自己的方块**：节点求值回调在服务端主线程与第三方系统直接交换数据，时序归本模组求值循环统一管理；**总线/私有信号保持玩家面**，第三方不接触总线时序。外部频道发布层（原 L1）**砍掉**。
3. **第三方求值代码在栅栏内**：可恢复契约（循环边界 yield 检查点，与 FORMULA 解释器同构）+ 独立重节点预算池；普通节点 µs 义务 + 墙钟埋点 + 升级处置梯子。
4. **API 签名零图域类型**——跨加载器窄口教训的结构性要求，API 必须是"值级"API。
5. 排期：先清现有 4 个独立小批，P2-7 并入节点波，节点波先于宿主套件波（§9）。

## 1. 背景与口径 / Background

### 1.1 为什么开 API

选型论证（cross-be §7.8/§7.10）留下的长期风险：**对世界的耦合面窄**——兜底通道（Create 红石链接）只能读写 0–15；读不了任意方块状态（库存/物流/机械相位），驱动不了非动力的 Create 执行器。1.3.0 公开 API = 这条窄口的正面解法。

### 1.2 目标与终态（2026-10-31 拍板）

目标消费者：模组开发者（Create 附属作者为主）。**四项能力全部进 1.3.0**（D1 拍板，否决了"终态分波"的保守建议）：

1. **节点注册**：第三方注册自定义节点类型（D2：完全自定义，求值逻辑外放）；
2. **图编辑器调用**：第三方方块/部件能调用图编辑器（D3：宿主套件）；
3. **图内通信**：在图中正常通信（既有总线/私有机制，玩家面不变）；
4. **数值读取**：数据交换（D6：节点直连提供者方块）。

## 3. 运行时硬约束 / Hard constraints

以下每条都已核实到代码。**约束是事实，决策可以改变约束的适用范围，但不能违反事实本身。**

1. **求值只在服务端主线程**：`GraphEvaluator` 客户端绝不实例化；客户端读路径唯一入口是 `EvalSnapshot` 快照。→ API 是**服务端专用**面。
2. **总线是 JVM 级静态、float32、按 String 名寻址**：跨维度共享，仅在 `ServerStoppingEvent` 清空；键名前缀 `channel\0band` 是结构性的。
3. **频道写入权有 owner 门控与收敛协议**：首注册者获胜、CLAIMANTS 排队、"已定义为空 vs 未定义"两态、"缺席不是定义"守卫。
4. **跨宿主写序未定义**：各宿主在各自 BE tick 里求值，同 tick 内跨方块可见性取决于 BE tick 顺序。
5. **节点面是封闭枚举**（`NodeType` 追加末尾、`NodeCategory` 全覆盖校验）——**D2 拍板后此约束演化为**：枚举管内置节点不变，第三方节点走**动态注册表**（字符串 id，与枚举共存）；undo/NBT/准入各面按字符串 id 口径设计。
6. **权威编辑协议**：图数据客户端不可直接写；修改走 op 通道（DAG 校验、服务端分配 ID、权威 editVersion）。→ 宿主套件的编辑器路由复用此面，不开旁路。
7. **预算与配额契约**：FORMULA 每服务端 tick 3 ms（可配）墙钟预算池、`slice = 预算/max(1, 上 tick yield 的重节点数)`、循环边界 `reportYield()` 跨 tick 推进（重脚本 ~3 s/解算即此机制）——**D2a 的可恢复契约与独立池直接复刻这套纪律**。
8. **引脚域严格二分**：FLOAT 与 AUDIO 不许混接。→ 第三方节点 v1 只做 FLOAT 域，音频域后议。
9. **宿主生命周期不可拆**：频道注册/冲突自愈/频段收敛/快照广播内嵌在 `GraphHost.tickBody` 骨架与卸载钩子。→ 宿主套件必须把第三方宿主接进这套骨架（组合式托管，见 §4 D3），不允许旁挂第二个 tick 入口。
10. **API 签名不得泄漏 Create/Sable 类型，且必须过跨加载器域**：含图域类型（`NodeGraph`/`EvalSnapshot` 等）签名的共享接口必须住 `graph./blocks.`；API 包作为最外层共享面**结构性禁止**引用图域类型。

## 4. 暴露面决策 / Exposure decisions

### 4.1 终态能力 → 1.3.0 两大件

| 能力 | 落地形态 | 决策 |
|------|---------|------|
| 节点注册 | **自定义节点系统**：动态类型注册表（`modid:node_id` 字符串 id）+ 求值分派扩展 + 声明式 schema + 通用渲染器 + 状态持久化 + 名单制准入 | D2 / D4 / D5 |
| 图编辑器调用 | **宿主套件**：第三方 BE 实现宿主接口（图存取/持久化钩子/准入偏好），接入 `GraphHost` 骨架，方块打开本模组编辑器 | D3 |
| 图内通信 | 总线/私有信号**保持玩家面现状**，不对外承诺 | D6 / D7 |
| 数值读取 | **节点直连提供者方块**：求值回调里直接与第三方系统交换数据 | D6 |

### 4.2 被砍掉的层（留档备查）

- **外部频道发布/订阅（原探索稿 L1）**：为"不想写节点的纯数据型第三方"设计的廉价路径。**D7 拍板砍掉**——它把总线时序（写后 ≤1 求值 tick 可见、跨宿主写序未定义）暴露给第三方，恰是节点直连模型要免掉的东西；纯数据型第三方仍有红石兜底（途径 1）。后续如有真实需求再立批。
- **程序化建图 API**（headless op 调用）：宿主套件之上的锦上添花，后置不立项。
- **第三方自绘节点 UI**：D4 砍掉——第三方代码不进客户端渲染路径。
- **异步节点车道**：D2a 砍掉——不接受 tick 级输出滞后。

## 5. 语义承诺 / Semantic commitments

**能承诺的**：

| 维度 | 承诺 |
|------|------|
| 执行线程 | 自定义节点求值回调在**服务端主线程**执行，由本模组求值循环调用 |
| 时序（节点直连） | 节点与提供者方块的数据交换发生在宿主求值 tick 内（同 tick 双向）；节点输出写入后按既有快照/广播纪律同步 |
| 重节点推进 | 可恢复节点按独立预算池的 slice 轮转跨 tick 推进，**输出在完成时才写**（与 FORMULA 重脚本同语义，无新增延迟类型） |
| 精度 | float32 端到端（引脚值、快照、总线同源） |
| 持久化 | 第三方节点状态随图 NBT 存取，随 RuntimeState 的保存/恢复纪律走 |
| 兼容 | 内置节点与既有语义不变；第三方节点 id 是稳定字符串，玩家图的持久化不因本模组更新损坏 |

**不承诺的**：

- 总线/私有信号对第三方开放（D6/D7：那是玩家面内部机制）；
- 客户端侧读 API（约束 1）；
- 音频域引脚（约束 8，v1 只 FLOAT）；
- 图对象形态的任何签名（约束 10）；
- 第三方自绘 UI（D4）；
- 未列名的内部 static 面一律内部语义，不背兼容债。

## 6. 包结构与兼容策略 / Packaging & compatibility

### 6.1 包位置与跨加载器域教训

- 新包 `io.github.y15173334444.create_schematic_compute.api`（实现侧另设内部包），**签名只用 JDK/MC 公共类型 + api 包自有值类型**（String/float/int/BlockPos/CompoundTag/自有 record）。
  **实施澄清（批 B 审查 (c)7）**：结构禁令的准确对象是「**api 签名中的图域类型**」（跨加载器约束的事实面）——api 门面到 graph 实现侧的**委托依赖**（如 `CustomNodes → CustomNodeRegistry`）是门面模式的实现边，不构成签名面，允许存在；方向纪律表述为「api 类型不引用图域类型；graph 域消费 api 值类型；门面单边委托实现」。
- 求值上下文以自有值类型形态交付（如 `float[]` 输入/输出访问器），**不出现** `GraphNode`/`NodeGraph`/`EvalSnapshot` 等图域类型——它们是 Sable 子世界优先复制域的类型（跨加载器窄口教训，解环批实证）。
- Create/Sable 类型零出现；客户端类零触碰（dist 纪律）。

### 6.2 版本承诺与弃用（默认口径，汇总时可否决）

- 1.3.0 起以 **experimental** 标注发布（接口签名、语义可变），**1.4.0 冻结**首个稳定面；冻结前破坏性变更走 CHANGELOG 明示。与"未发版形态不写兼容"口径一致。
- 冻结后弃用：保留旧签名 ≥1 个大版本 + 编译期弃用标注 + CHANGELOG 明示。

### 6.3 分发形态（默认口径）

**同 jar 公开类 + 源码附件 + api 包 javadoc**；不另拆 artifact、不建 maven 发布（与本模组消费 Create 的 Modrinth Maven 形态对称；拆分对消费者是零成本迁移，留到第三方成规模再议）。

## 7. 安全与权限 / Security & permissions

- **信任模型**：API 消费者 = 服务器上安装的模组 = 完全可信代码（与 mixin 作者同级）。不做 OP/gamerule 门控。
- **节点准入名单制（D5）**：默认拒绝、显式登记——第三方把自己的节点 id 登记进目标宿主的准入名单（自己的宿主套件随便登记；本模组方块走本模组提供的登记口）。名单制与 **P2-7（节点准入服务端化，已拍板运行时校验带旧档兼容口径）同域合流**：服务端 op 链校验"节点 id 在该宿主名单内 + 提供方在线"，改包客户端塞不进未登记节点。
- **求值栅栏（D2a）**：第三方代码跑在主线程但进不了预算池外的执行路径——可恢复节点只在拿到 slice 时被推进；普通节点超阈值进升级处置梯子（告警→降频→熔断），日志带 modid+节点 id。
