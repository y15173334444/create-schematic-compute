> 后静默丢弃，限流只是缓解）——按 eval §三 的升级条件启动 B 路线**「自管混音层」引擎**，作为

>   （STREAMING 声部池）输出——**声部消耗恒为 1**，与曲目密度无关；并发上限 = 混音器

> - **采样**：原版音符盒 16 音色运行时从原版资源解码（`JOrbis` → 单声道 PCM 缓存）——
>   **引用 ≠ 再分发**（D13 法务口径），jar 不含采样资产。
> - **衰减/声像（F7 + D13）**：`gain = 1 − dist/radius` 线性衰减，radius 取音响 `radius`
>   覆盖（>0）或默认 48 格——**`radius` 字段自此有消费者**；声像 = 听者右手系横向分量等功率。
> - **时序口径**：输出 80 ms 小缓冲回填（通道恒预填 4 块 ≈ 320 ms 输出余量，扛 GC 级停顿）；
>   相对时序（同 tick 子 tick 偏移）精确，绝对延迟由预播提前量对冲（见 R2 补）。
> - **弃选**：声部限流/优先级（过渡缓解，被引擎替代）；多基准采样集（需原创录音，法务不可
>   行——软件重采样越窗音质下降）。
>
> **R2 补（2026-10-02，参照 Note Block Studio 播放模型 / OpenNBS·MIT）**：
> - **乐器索引序修正（真 bug）**：曲目乐器字节按 **NBS 格式序**解读（0=harp, 1=bass, 2=basedrum,
>   3=snare, 4=hat, 5=guitar, 6=flute, 7=bell…，以 NBS 自家 `dat_instrument` 为准）——原先误用
>   原版枚举序，**1–7 号乐器放错音色**；编辑器乐器标签同步纠正。
> - **全音域播放（F1 口径更新）**：音高公式对齐 NBS（`0.5×2^((key−33)/12)`，基准键 45），键 0–87
>   全部发声（软件重采样，越窗为拉伸保真度降级而非钳制失真）；**33–57 精确窗口语义保留**
>   （零拉伸区间）。原「窗口外钳制」取消——该口径是原版播放引擎（pitch 钳 0.5–2.0）时代的
>   能力边界，自管引擎已不存在此限制。
> - **破音修复（增益分级）**：混音渲染改**块级包络限幅**（峰值超 0.95 才压，attack 即时、
>   release ≈250 ms），替代逐样本软限幅（后者在超密和弦下长时间满幅 = 听感「破音」）。
>   **不做采样峰值归一化**（作者口径 2026-10-02 确认）：乐器间录音响度差是音乐平衡的一部分，
>   归一化会抹平相对响度、抬高整体电平反而更常撞限幅器（动态变差）——保留原始电平，
>   余量由限幅器兜底（NBS 同样依赖原始电平）。
> - **预播提前量（plan 抛光项落地）**：服务端提前 0.2 s 展开音符、事件携带目标时刻
>   （`delaySeconds` = 自下发到音符目标的乐理秒数）；客户端落点 = 墙钟增量 + 目标 − 预播——
>   服务端 tick 过载时「晚点/成批」的到达抖动由此吸收（此前「密集段落推迟/挤堆」的服务端侧根因）。
> - **NBS 采样不采用（法务）**：哈希比对确认其 `harp.ogg` 与 MC 原版 `sounds/note/harp.ogg`
>   字节一致——采样集含 MC 提取物，MIT 只覆盖代码，不可再分发进 jar（与内置测试曲同红线）；
>   维持运行时引用原版采样（D13「引用 ≠ 再分发」口径不变）。
>
> **播放引擎修订 R3（2026-10-03，作者驱动）**：CHANNEL 的「输出声道数 1..7」改为**标准布局预设**
> （`ChannelLayout` 纯类，`params[0]` = 布局序号），引脚集合由布局表整体决定，并补齐全部声道
> 的拆分语义（此前 c/ls/rs/sub 为全量拷贝占位）：
> - **布局表**：MIX=聚合（mix）；STEREO=2.0（l, r，新建默认）；QUAD=4.0（l, r, ls, rs）；
>   5.1（l, r, c, sub, ls, rs）；7.1（l, r, c, sub, ls, rs, sl, sr）。
>   `CHANNEL_PIN_IDS` 扩为九值（新增 sl/sr；sub 移到 c 后），顺序兼作 SPEAKER_PLAY 声道序号。
> - **拆分口径**（只依赖音符自身 pan/乐器/键位）：mix 恒等；l/r 在无中置布局用等功率对
>   （cos/sin(p·π/2)，NBS 同款），含中置布局改 LCR 三角（p&lt;0.5：L=cos(pπ)、C=sin(pπ)；
>   p≥0.5：C=cos((p−0.5)π)、R=sin((p−0.5)π)），能量守恒、中心归 c；c = LCR 中心分量；
>   sub = 低音乐器（bass/basedrum）或极低键位（key&lt;24）全增益、其余不进——NBS 无频谱信息，
>   乐器/音域是唯一可靠「低音」判据；ls/rs = 极左/极右溢出带（p&lt;0.25 余弦渐入，右对称）；
>   sl/sr 与 ls/rs 同口径（NBS 声像无深度信息，侧/后区分靠音响摆放）。权重低于 −80 dB
>   视为数值噪声（cos(π/2)≈6e-17）不进该声道。
> - **迁移**：旧「前 N」节点（mix 开头的旧序连续前缀）在 NBT 载入时迁移：1→MIX、2/3→STEREO、
>   4..7→5.1（旧 7 去掉 mix 恰为 5.1 全集），引脚立即重建；消失引脚的连线由
>   `rebuildInputCache` 的 stale 剪枝收走（布局切换的 SET_PARAM 同路）。v1.2.6 未发布，
>   迁移只保语义不保连线。
> - **SPEAKER_PLAY**：声道参数从 0/1/2 硬编码扩为全声道序号（`channelIndex`/`channelName`，
>   旧值语义不变）；直连全带源时选任意声道，接已拆声道的 CHANNEL 输出时保持 mix（恒等），
>   否则二次衰减。
> - **边界**：客户端混音不变——每只音响仍是单点声源、立体声输出、几何 pan；多声道空间感
>   = 多音响各播一声道（R1-5 口径）。`NoteEventPacket`/`AudioBands`/`OpType` 零协议变化。

## 〇、设计修订 R1（2026-10-01，作者驱动）/ Design Revision R1

> 作者对初版实现提出的关键修正：① 音频连线是**类型化音源引用**（同 UE 向量/音频引脚 ≠ 浮点）；
> ② 音频**走总线/私有信号频段**路由（复用既有频段基建，不另建音频频道注册表）；③ 频段型音频引脚
> **随可用频段自动增减**；④ **音响也是图宿主**（音频专用图），非哑端点。本节覆盖下文初版的
> D1/D5/D10/D11 与 §3.4「姊妹注册表」等结论。

**R1-1 音源引用 AudioRef（类型化「传输」）**
- 音频连线上跑 **`AudioRef`**（类型化音源引用），**不是浮点**——即「向量 vs 数值」之别。
- `AudioRef` = 不透明类型引用，指向**活音源**（曲目 + 传输状态 + 增益链）。MUSIC 造、AMP 改增益、sink 消费；沿 AUDIO 域连线**按引用**传递（拓扑序：源在汇前）。
- 类型规则：**AUDIO 引脚 ↔ AUDIO 引脚**才可连（pin domain 校验，已有；内部改为类型化音源表，不再滥用浮点数组当句柄）。

**R1-2 音频经总线/私有频段路由**
- 音频信号（本 tick 音符事件）经**总线/私有频段**（`SignalBus` 频段基建）路由：频段名 = 路由。
- 音频节点的频段型引脚（引脚名 = 频段名）**随可用频段自动增减**（`BusChannelHelper.convergeBusInBands` 同款收敛）。
- 复用既有频段注册/收敛/冲突/生命周期纪律；**废弃并列的 `AudioChannelRegistry`**（并入频段层）。

**R1-3 音响 = 音频专用图宿主**
- 音响 = `SyncedGraphBlockEntity` 图宿主 + **音频专用图编辑器**。
- 图节点集（音频专用）：`BUS_IN`（频段读——输出接音频线走音频分支；**2026-10-03 修订：AUDIO_IN 移除**，
  频段读取由走总线/私有频段路由的音频连线承担）→ `AMP`/混合 → **`SPEAKER_PLAY`（在本坐标播放 sink）**。
- 处理后的音源在音响坐标发声；红石静音兜底保留。

**R1-4 节点集（修订）**
- 功放图：`MUSIC`（曲目宿主，产 AudioRef）/ `AMP`（增益，产 AudioRef）/ `AUDIO_OUT`（把音源发布到总线/私有频段）。
- 音响图：`BUS_IN`（频段读——输出接音频线走音频分支）/ `SPEAKER_PLAY`（本坐标播放 sink）+ 少量处理（AMP/混合）。
- 全部归 `NodeCategory.AUDIO`；功放准入 = 通用+AUDIO，音响准入 = 音频专用（AUDIO 类 + 播放 sink）。

**R1-5 多声道 / 声道（channel）—— 已定稿**
- 音频信号是**多声道**（声道数 N：1=单声道 / 2=立体声 / …），含**聚合声道（mix）** + 各独立声道（左 L / 右 R / …，环绕可扩）。
- **`CHANNEL`（声道）节点 = 声道拆分（多引脚）**：编辑区选**输出声道数**（N），把输入音频**拆成多个独立声道引脚**（聚合/左/右/…）。下游各引脚各连其一。
- **音频引脚的声道显示**：接音频线的节点在引脚上**显示当前输入声道**（聚合/左/右/…）——即连接携带声道语义，节点标注所接声道。
- **声道 ↔ 音响（多只布局）**：左/右声道分别路由到**不同音响**播出；用多只音响布局实现立体声/空间声像（左声道→音响A、右声道→音响B）。聚合声道可接单只音响（下混发声）。
- 声道名：聚合（mix）、左（L）、右（R）；环绕扩展（中置/左环绕/右环绕/低音）后续。
- 与声像/世界位置关系：立体声可按曲目声像（NBS panning）分布到左/右；空间声像仍由听者相对音响世界位置决定（eval §四.3）。

**返工范围（初版 → R1）**：AudioRef 类型化 + 求值器音源表、音频路由并入总线/私有频段（含自动频段引脚）、音响升图宿主 + 音频专用图、节点集调整（增 AUDIO_IN/SPEAKER_PLAY，AUDIO_OUT 改发布到频段）。下方 §二/§三/§四 初版描述以本节为准。

## 一、核心结论 / Core Conclusions

1. **产品形态**：新增两个方块——**功放电脑**（图宿主 + 内置 NBS 音乐编辑器 + 音频频道发布）与**音响**（哑端点，绑定频道名，在自身世界坐标发声）。
2. **连接模型 = pinId 定址的三层**：① 同图**音频域特殊连线**（音频引脚间，pinId 绑定纪律与普通连线相同）；② 跨方块**频道绑定**（音频引脚 pinId = 频道名 ↔ 音响按名订阅，BUS_OUT 频段名同款约定）；③ **控制面**（播放/停止/音量）走总线/私有浮点信号（通道分层主力层），红石作兜底。
3. **播放引擎（MVP）= 原版声事件映射**：NBS 乐器 0–15 → 音符盒 16 音色；键 33–57 精确、窗口外钳制；力度→音量；声像由世界位置取代。自研采样引擎留作升级路线（eval §三）。
4. **音频连线承载音源引用**（哪首曲目 + 传输状态），图做路由/控制、编辑器做时序；不做逐音事件流。
5. **调度 = 服务端权威排程 + 每音符下发**：事件包带子 tick 目标时刻，客户端定点播；多音响同 tick 天然同步。
6. **曲目数据住在 MUSIC 节点上**（IMAGE 像素同款数据面），双击节点打开 NBS 编辑器（像素编辑器同款管线）。
7. **控制语义沿用既有约定**：播放/停止 = 触点上升沿（`nodeEdge` 去重）、跳转 = 边沿快照数值、增益 = 浮点引脚；跨机控制全部复用既有总线/私有信号，**不新增控制传输机制**。
8. **诚实边界**：这是「NBS 转录演奏」不是「乐器实体」；精确音域 = NBS 键 33–57；自定义乐器 MVP 只保数据不发声（eval §四）。

## 二、需求与术语 / Requirements & Terminology

需求条目（用户原话归纳）：

- 功放电脑方块（**内置 NBS 音乐编辑器**）+ 音响方块（**让声音出现在世界位置**）；
- **通过 PINid 指定特殊连线和节点连接（可通过总线/私有信号）**；
- 版本 1.2.6；先仅写文档，不写代码/模型。

术语表见 eval §一。本节补**连接矩阵**（"PINid 指定特殊连线和节点连接"的机制展开）：

| 场景 | 机制 | 定址载体 | 示例 |
| --- | --- | --- | --- |
| 同图直连 | 音频域特殊连线（渲染特殊样式） | 连线 pinId（v1.2.4 纪律） | 曲目节点 → 增益节点 → 频道引脚 |
| 跨方块/跨机音频路由 | 音频频道（全局注册表，按名发布/订阅） | **引脚 pinId = 频道名**（BUS_OUT 频段名同款） | 功放图「舞池」频道引脚 ↔ 各处音响绑定「舞池」 |
| 控制面（播放/停止/音量/选曲） | 既有总线/私有浮点信号 + 节点引脚 | 信号名 | 另一台计算机 PRIVATE_OUT「点歌」→ 功放图 PRIVATE_IN → 曲目节点 seek |
| 兜底控制 | 红石输入 | 电平 | 音响红石高电平静音（互操作兜底） |

## 三、总体架构 / Architecture

### 3.1 方块与 BE

```
AmplifierComputerBlock（普通 GraphBlock，Monitor 同线）
AmplifierComputerBlockEntity extends SyncedGraphBlockEntity   ← 图宿主薄壳，recompileEvaluatorFull（含时序节点）
SpeakerBlock（普通方块，红石输入 + GUI）
SpeakerBlockEntity extends BlockEntity                        ← 无图哑端点
```

- **功放电脑**：走继承线（`SyncedGraphBlockEntity` 薄壳 + `GraphHost` 引擎），复用全部图/求值/同步/BUS 生命周期基建；类型段（`loadTypeSpecific`/`saveTypeSpecific`/`acceptTypeSpecific` 钩子）承载传输状态与编辑器设置。求值器宿主注入沿用既有范式（雷达位置注入同款）：重编译后重新注入音频句柄表。
- **音响**：无图。字段 = 频道名、增益、半径覆盖（0 = 跟随声音定义）、静音态；服务端持有频道订阅，`setRemoved`/卸载退订。
- **视觉/模型**：按用户要求本期不做；占位几何先行，贴图雕刻与粒子视觉后补。

### 3.2 NBS 音乐编辑器（功放电脑内置）

- **入口**：图编辑器中**双击 MUSIC 节点**打开（像素编辑器同款管线：实现 `GraphEditor.Host` 使整图同步守卫与 sendOp 计数生效；关闭后恢复图编辑器或终端包装；从便携终端打开同样可用）。
- **形态**：钢琴卷帘（tick 横轴 × 键纵轴）+ 层面板（名称/音量/声像/锁定）+ 传输条（播放/停止/循环/速度显示）+ 试听（编辑器内用同款播放路径，按听者位置发声）+ 导入/导出 .nbs。
- **拆分**（沿 GUI 拆分路线）：纯内核（曲目编辑操作 + 撤销/重做状态机，无 MC 依赖，可单测）/ 钢琴卷帘 / 屏幕（布局与输入路由）三件。
- **编辑会话**：本地编辑 + 保存走既有保存请求（服务端权威落盘 + 回弹保护三护栏同款）；多人逐音协作 op 列后续（见 §八）。

### 3.3 图节点与音频引脚域

节点引脚引入**域标注**（FLOAT / AUDIO）：AUDIO 域引脚只连 AUDIO 域，连线渲染**特殊样式**（"特殊连线"的视觉面）；pinId 解析约定与普通引脚一致（H1）。求值器内音频引脚经**音源句柄表**传递（曲目引用 + 传输状态），不混入浮点输出数组。

| NodeType | 输入引脚 | 输出引脚 | 参数 | 语义 |
| --- | --- | --- | --- | --- |
| `MUSIC` | play（触点）、stop（触点）、seek（tick 数值） | audio（AUDIO 域）、playing、tick、seconds、done | loop | 曲目宿主：数据住节点（NBS 二进制），双击开编辑器；play/stop 上升沿生效（`nodeEdge` 去重）、seek 上升沿当帧快照（指令节点同款）；done = 非循环播放到尾一帧脉冲 |
| `AMP` | audio、gain | audio | gain 默认 1 | 「功放」本义：增益（钳 0..4）、可接图信号做音量自动化 |
| `AUDIO_OUT` | 每频道一个 audio（动态引脚） | — | 频道名列表 | 频道发布：引脚 pinId = **频道名**（BUS_OUT 频段名同款），冲突语义同 BUS（冲突方不发布） |

节点分类新增 `AUDIO` 类（分类边界原则：方块整类接受或不接受）；准入名单只给功放电脑。

### 3.4 音频频道与「特殊连线」（注册表）

新增**音频频道注册表**（信号总线的姊妹表，生命周期纪律同款）：

- **发布**：AUDIO_OUT 求值输出 → 写本 tick 频道音符事件；owner = 方块坐标+节点 id（同既有频道 owner 语义）；同名不同 owner → 冲突旗标，**冲突的发布方不拥有频道**；注销按引用计数，卸载/删除即退订（信号总线泄漏教训同款）。
- **订阅**：音响 BE 按频道名订阅；订阅不拥有频道，发布方可缺席（缺席不是定义，同既有收敛纪律）。
- **分发**：服务端按「订阅音响位置 × 追踪玩家」组包下发（见 3.5）。
- **命名空间**：音频频道名与浮点频道名同一命名池做冲突提示（编辑器提示「该名已被浮点频道占用」），机制上分表隔离。

### 3.5 播放调度与数据面

```
服务端 tick：
  图求值 → MUSIC 传输状态推进（playing 起点游戏时刻 + 曲目时间轴）
        → 展开「下一窗口内落到的音符」为频道音符事件（乐器/键/cents/力度/子 tick 目标时刻）
        → 音频频道注册表分发 → 按订阅音响与追踪玩家组包 NoteEventPacket（每 tick 每玩家一包，聚合多频道）
客户端：
  收包 → 按目标时刻定点播（到达 + 预播提前量）→ 自定义声实例（世界位置=音响坐标、音源类别=唱片/音符盒）
       → 原版声事件映射表（乐器 → 音符盒 16 音色；键 33–57 → 0..24；窗口外钳制；cents → 音高倍率；力度 → 音量×增益）
```

- **同步性质**：同一服务端 tick 的事件对所有客户端同时下发，多音响同 tick 天然对齐；跨端绝对延迟 = 网络 + 预播提前量，精度口径 = ±1 游戏刻 + 子 tick 偏移尽力（eval §四.4）。
- **数据面**：曲目 = NBS v5 原始二进制存 MUSIC 节点可选 NBT 键（IMAGE 像素同款直存）；**大小上限**超限拒存并提示（阈值建议 256 KB，估算，实现期定）；Blob 分片搬运输列后续。新增 op（曲目写入/曲目替换）进操作执行器与撤销体系（草稿/权威数值分离的既有纪律）。
- **声音事件**：注册自有声音事件名**引用原版采样文件**（引用≠再分发），衰减距离按事件定义定制（F3 的机制给了这个自由度；静态推断，实现期验证跨命名空间文件引用）；验证失败则回退「直接用原版 16 事件、固定 48 格」。

### 3.6 控制面（总线/私有为主力、红石兜底）

- 图内：play/stop 触点、seek 数值、gain 浮点——全部普通引脚，与既有节点自由组合。
- 跨机：PRIVATE/BUS 浮点信号进功放图（点歌、音量、急停），**不新增任何传输机制**（通道分层口径：总线/私有=主力、红石=兜底、本功能不涉动力执行面）。
- 兜底：音响红石输入高电平静音（与原版/他模组互操作）。

### 3.7 多人 / 持久化 / 迁移

- **服务端权威**：传输状态、频道注册、事件排程只在服务端推进；客户端只消费事件包与快照。传输状态经 BE 类型段 NBT 持久化（存档恢复语义沿用统一恢复入口）。
- **编辑**：图与曲目编辑走既有 op/保存协议 + 回弹保护三护栏；曲目本地编辑会话（像素编辑器同款：本地改、保存落盘）。
- **迁移**：新节点类型 + 可选 NBT 键 + 新 BE 类型段，旧档无感（IMAGE 等节点先例）；不升数据版本号（D12，待确认）。音频连线复用既有 pinId 字段格式，无连线结构变更。

## 六、风险清单 / Risks（按严重度）

1. **[高] 声部池静默丢音**（F6）：高密度和弦 × 多音响打满 OpenAL 静态池后声音无声丢失。缓解：声部限流 + 优先级；压力用例进验证清单（P1）。
2. **[高] 声音事件跨命名空间引用不成立**（D13 静态推断）：自有事件引用原版采样文件若在目标环境解析失败 → 全部无声。缓解：实现期第一件事验证；失败回退 D13 弃选（原版 16 事件直用）。
3. **[中] 播放精度与抖动**：tick 网格 + 网络延迟导致快节奏乐句抖。缓解：子 tick 目标时刻 + 预播提前量；文档声明精度口径。
4. **[中] 大曲目同步膨胀**：曲目进图 NBT 后全图同步包变大（IMAGE 像素同款账单）。缓解：大小上限 + 拒存提示；Blob 分片后续。
5. **[中] 事件包量**：和弦密集时每 tick 事件多。缓解：每玩家每 tick 一包聚合；事件字段压紧（乐器/键/cents/力度/偏移）。
6. **[中] 多人编辑曲目冲突**：本地会话 + 保存落盘 = 后保存者胜（像素编辑器同款账单）。缓解：回弹保护三护栏复用；逐音 op 后续。
7. **[低] Sable 子世界位置**：音响装在旋转结构上，发声坐标需随子世界变换。缓解：位置取变换缓存同款机制（渲染侧已有先例）；列为兼容项验证。
8. **[低] 与唱片机/音符盒同类别音量**：SoundSource 取「唱片」类别与音符盒共享滑条。缓解：语义上合理（音乐类）；文档注明。

4. **SPEAKER 虚拟节点**（图上直接摆音响代理）：与「频道绑定」重复，暂不做；若做则 pinId=音响绑定名同款寻址。
5. **逐音协作 op**（多人同时编辑曲目）：先本地会话+保存落盘。
6. **Blob 分片搬曲目**、**MUSIC 播放速度引脚**（变速不变调另议）、**循环点可视化编辑**（NBS 循环字段先按导入值生效）：后续。
7. **编辑器键位入键位系统**：MVP 厂内快捷键（像素编辑器旧做法），后续入既有键位绑定。
8. **命名**：产品名暂用「功放电脑/音响」（用户口径）；对外英文名拟 *Amplifier Computer / Speaker*，发布前定稿。
9. **D13 回退条件**：若跨命名空间采样引用验证失败，声音方案整体降级为原版 16 事件直用（衰减固定 48 格），其余设计不变。
