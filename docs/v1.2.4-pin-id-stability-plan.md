# v1.2.4 优先：稳定 pinId 重构（根治 bus / 公式动态引脚 / 封装 I/O 连线一致性）

> 版本定位：原计划中「稳定 pinId（方案 3）」在 [`v1.2.5-plan.md` §3.3](./v1.2.5-plan.md) 被定为「后续长线，不在 v1.2.5 必做」；[`formula-pin-render-tech-debt.md`](./formula-pin-render-tech-debt.md) 仅把 FORMULA 的**临时修复**（消除 `inputLabel()` 副作用）提前到 v1.2.4，根因（整数索引绑定）仍留作长线。
>
> **本次调整**：总线（bus）系统也暴露了同类问题（`BusChannelHelper.syncBandsFromServer` 在频段变更时暴力清空全部连线）。三类动态引脚（bus 频段、FORMULA 输入、ENCAP 子节点）根因相同——**连线用整数 `fromPin/toPin` 列表位置索引绑定，引脚集合/顺序变化时索引失效**。故将稳定 pinId 重构**提前到 v1.2.4 作为根因修复**，一次解决三者。
>
> 范围：只写方案，不改动源码（基于 `c38c5bf`）。

---

## 0. 动机与收益

| 系统 | 触发条件 | 现状症状（整数索引绑定） |
|------|----------|--------------------------|
| **BUS 频段** | 插入/重排/删除中间频段 | 连线按位置索引错位；`syncBandsFromServer` 直接清空全部连线 |
| **FORMULA 输入** | 公式增/删变量 | 连线消失或画在错误 Y 位置（每次按键可能触发） |
| **ENCAP I/O** | 拖动 I/O 子节点改变 Y 排序 | 连线跟错引脚 / 数据流翻转 |

统一根因：连线身份 = `(fromId, fromPin)` / `(toId, toPin)` 的**整数位置索引**，而非稳定引脚标识。引脚被增/删/重排时，旧索引指向了不同的引脚。

**稳定 pinId 的收益**：引脚一旦创建就获得不可变 `pinId`，连线绑定 `pinId`。重排/插入/删除引脚**天然不破坏连线**，无需 `REWIRE` 重编号逻辑（直接消灭 `v1.2.5-plan.md` 方案 2 的复杂性）。

## 2. 目标设计

### 2.1 核心
为每条引脚赋予**不可变稳定 `pinId`**，连线改存 `fromPinId/toPinId`（字符串），以 `pinId` 作为连线身份。渲染/命中测试时再由 `pinId → 当前整数索引` 映射（索引仅用于画点/画线位置，不再决定连线归属）。

### 2.2 各系统 pinId 来源（天然稳定标识）
| 系统 | pinId 取什么 | 为什么稳定 |
|------|--------------|------------|
| **FORMULA 输入** | 变量名 `cachedScript.inputVars.get(i)`（如 `A`、`B`、`x`） | 变量名即语义标识；增删变量时，已存在变量名不变，连线按名跟随 |
| **ENCAP I/O** | 子节点自身 `nodeId`（`countSubNodes` 遍历到的 ENCAP_INPUT/OUTPUT 的 `id`） | 子节点 id 不随 Y 排序改变；拖动只改位置不改 id |
| **BUS 频段** | 频段名 `signalBands.get(i)`（如 `band_0`、`band_1`） | 现有自动命名已唯一稳定；插入/重排中间频段时，`band_0` 等名不变 |

> 统一为 `String` 存储（`pinId = String.valueOf(subnodeId)` 用于 encap），避免 int/String 双轨。

### 2.3 关键推论
- **重排不再需要 REWIRE**：ENCAP 拖动 I/O、BUS 重排频段只改变「pinId→index」映射，连线身份（pinId）不变 → 连线自动跟随，根除 `v1.2.5-plan.md` 方案 2 的「落定重编号」逻辑。
- 仅 **增/删引脚** 改变连线集合，走现有 connect/disconnect op 即可（删引脚时断开该 `pinId` 上的连线）。

## 4. 迁移策略（旧图兼容）

旧图存整数 `fromPin/toPin`，无 `pinId`。加载时按节点类型 + 当时顺序映射为 pinId：

- **FORMULA**：`pinId = inputVars.get(oldIndex)`（变量名，按保存时顺序）；输出同理用 `outputLabels`。
- **ENCAP_INPUT/OUTPUT**：`pinId =` 按 Y 排序的第 `oldIndex` 个子节点 `id`。
- **BUS**：`pinId = signalBands.get(oldIndex)`（频段名）。

加载后 pinId 立即持久化，后续读写均以 pinId 为准。旧字段 `fromPin/toPin` 在迁移完成后可废弃（保留一个版本过渡）。

> 注意：若旧图保存时 `dynamicInputCount` 等计数与公式不符（NBT 重载场景），FORMULA 迁移需先 `ensureScriptParsed()` 得到正确 `inputVars` 顺序。

## 5. 多人协同

- `pinId` 是节点状态的一部分（频段名随 `BusBandUploadPacket` 同步、子节点 id 随节点同步、变量名随 `SET_FORMULA` 同步），连线 op 携带 `pinId` 后天然正确。
- **不再需要 REWIRE-on-reorder**：一端重排引脚（ENCAP 拖动 / BUS 重排），另一端收到的只是节点重新排列，连线 `pinId` 不变 → 渲染自动跟随，无额外广播。
- 仅「增/删引脚」产生 connect/disconnect op，与现有协同协议一致。

## 9. 风险

- **频段名 / 变量名重名或改名**：pinId 唯一性需约束（bus 自动命名已唯一；formula 变量名按解析结果，重名时取首个）。改名（如把 `band_0` 改名）应视为「断该 pinId 连线」，与现有语义一致——如需保留连线，应在改名时做 pinId 重映射（可选增强）。
- **序列化兼容**：旧图迁移务必在加载期一次性完成并回写，避免新旧混存。
- **性能**：`pinIndex(pinId)` 为线性查找，引脚数量小（≤26/≤16），可忽略；encap/bus 可缓存 `pinId→index` map 在 `bandsDirty`/`markDirty` 时刷新。
