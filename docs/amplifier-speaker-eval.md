## 一、需求重述与术语 / Requirements & Terminology

需求条目（用户原话归纳）：

- 新增**功放电脑方块**（内置 NBS 音乐编辑器）+ **音响方块**（让声音出现在世界位置）；
- 连接方式：**通过 PINid 指定特殊连线和节点连接（可通过总线/私有信号）**；
- 该功能版本号 **1.2.6**；先仅写文档，不写代码/模型。

| 术语 | 含义 |
| --- | --- |
| 功放电脑 / Amplifier Computer | 图宿主方块：节点图 + 内置 NBS 音乐编辑器 + 音频频道发布。「功放」语义 = 增益/路由/混音由图程序驱动 |
| 音响 / Speaker | 世界位置播放端点：绑定音频频道，在自身坐标播出声音（哑端点，见计划 D1） |
| 曲目 / Song | 一首 NBS 歌曲的完整数据（音符 + 层 + 元数据 + 循环设置） |
| 音频频道 / Audio Channel | 按名寻址的音符事件通道；发布方 = 功放图的频道引脚，订阅方 = 音响 |
| 特殊连线 / Special Wire | 双义，均以 pinId 定址：① 图内**音频域连线**（音频引脚之间，渲染特殊样式，pinId 绑定纪律与普通连线相同）；② 跨方块的**频道绑定**（音频引脚 pinId = 频道名 ↔ 音响按名订阅） |
| 音源句柄 / Source Handle | 音频连线上承载的引用（哪首曲目 + 传输状态），不是逐音事件流 |
| 传输 / Transport | 播放状态机：播放/停止/跳转/循环（playing、起点游戏时刻、速度） |
| 控制面 / Control Plane | 播放、停止、音量等**浮点语义**控制——按通道分层口径走总线/私有信号（主力层），红石为兜底 |

## 二、已核实事实 / Verified Facts

> 以下 F/G/H 全部**逐行核对**源码或官方规范；少数推断项在行内注明「静态推断，实现期验证」。

### F1–F7 Minecraft 声音引擎（`build/neoForm` 反编译源，1.21.1）

| # | 事实 |
| --- | --- |
| F1 | **音高钳制 ±1 八度**：`SoundEngine.calculatePitch` = `clamp(pitch, 0.5, 2.0)`；音符盒 `getPitchFromNote(n)=2^((n−12)/12)`、n∈0..24，恰好就是该窗口 |
| F2 | **音量钳制**：`calculateVolume = clamp(实例音量 × 音源类别音量, 0, 1)`——可听响度封顶 1 |
| F3 | **衰减半径来自声音定义**：`play()` 内 `range = max(音量, 1.0) × 声音定义的 attenuation_distance`（sounds.json，默认 16 格）；实例音量 >1 只延长距离。音符盒用音量 3.0F → 48 格 |
| F4 | **服务端广播路径**：`ServerLevel.playSeededSound` → `ClientboundSoundPacket`（位置+音量+音高+种子）按 `getRange(volume)` 发给追踪玩家；`ClientLevel.playSeededSound` 仅当首参=本地玩家才本地播——音符盒的 `blockEvent` 客户端分支只加粒子，声音只来自 sound 包，无双播 |
| F5 | **音色枚举**：`NoteBlockInstrument` = 16 个可调基础乐器（harp/basedrum/snare/hat/bass/flute/bell/guitar/chime/xylophone/iron_xylophone/cow_bell/didgeridoo/bit/banjo/pling）+ 6 头颅仿声 + 自定义头。NBS 乐器 0–15 与 16 基础乐器一一对应 |
| F6 | **声部池会满**：OpenAL 静态池 = clamp(N−√N, 8, 255)、流式池 = clamp(√N, 2, 8)（N=设备通道数）；池满时 `acquire()` 返 null，该声音**静默丢弃**（仅 IDE 警告） |
| F7 | **声实例能力**：`SoundInstance` = 世界位置 + 音量 + 音高 + 循环/延迟 + 相对标志 + 衰减模型（LINEAR/NONE）；自定义 `AbstractSoundInstance` 经 `SoundManager.play` 播放——任意位置发声是原版就有的能力 |

### G1–G3 NBS 格式（Note Block Studio 官方规范）

| # | 事实 |
| --- | --- |
| G1 | **现代格式 v5 结构**：头（版本字节/原版乐器数/曲长 tick/层数/曲名/作者/原作者/描述/速度=每秒 tick×100/拍号/循环开关+次数+起点 tick）+ 音符段（tick·层跳跃编码；乐器字节 0–15 原版、≥16 自定义；键 0–87 = A0..C8；力度 0–100；声像 **−100..+100 有符号字节、0=居中**（OpenNBS 官方规范；实现内存约定 0–200、100=居中，I/O 边界需换算——handoff P1-4）；细音高 cents ±32767、编辑器限 ±1200）+ 层段（名称/锁定/音量 0–100/声像 −100..+100 有符号、0=居中）+ 自定义乐器段（0–240 个：名称/音色文件/基准键 默认 45=F#4/按键标记） |
| G2 | **换算**：总音高 = 键×100 + 细音高（cents）；音量 = 层×音符/100；声像 = 层=100 取音符，否则 (层+音符)/2（符号性见 G1 勘误）；默认速度 10 tick/s → 1 tick = 100 ms = 2 游戏刻 |
| G3 | **键位窗口**：NBS 键 33–57（F#3..F#5）恰为音符盒 0–24 的两八度窗口；全音域 0–87 超出 F1 钳制窗口 |

### H1–H3 本仓机制

| # | 事实 |
| --- | --- |
| H1 | **pinId 纪律（v1.2.4+）**：连线绑定稳定 pinId（FORMULA=变量名、ENCAP=子节点 id、BUS_OUT 入/BUS_IN 出=频段名、通用=十进制索引），拓扑变化重解析并剪除失效连线；新引脚类型只需加入 pinId 解析约定 |
| H2 | **信号分层现状**：信号总线 = 扁平私有信号表（名→float，PRIVATE）+ 频道注册表（名→条目{输出映射, owner, 引用计数}，BUS_OUT）+ 频段注册表；同名不同 owner → 冲突旗标，**冲突的发布方不拥有频道**；注册/注销按引用计数走生命周期 |
| H3 | **大数据面先例**：IMAGE 像素 int[] 直接进图 NBT；op 可带 blob 引用经分片注册表传输（≤30KB/片，类型枚举含 RAW_BYTES 扩展点） |

## 三、播放引擎路线对比 / Playback Engine Routes

> **结论先行：选 A（原版声事件映射）做 MVP；管线按可升级性设计。B 仅在需求变化时启动。**

| 维度 | A. 原版声事件映射（选定） | B. 自研采样引擎 |
| --- | --- | --- |
| 机制 | 音符事件 → 原版 SoundEvent（F5 的 16 音色）+ 声实例音高/音量/世界位置 | 自带采样 + 多八度映射或自研混音（要绕开 F1 钳制只能自带多基准音高采样集，或自管 OpenAL 层） |
| 键位保真 | 键 33–57 精确；窗口外钳制（见 §四.1） | 全 0–87 |
| 自定义乐器（G1 ≥16） | 不支持：导入保留数据，播放降级 + 提示 | 支持（自建音色包） |
| 细音高 cents | 窗口内精确（声实例 pitch 即频率倍率） | 精确 |
| 力度/声像 | 力度→音量 OK；声像→世界位置取代（语义差异，见 §四.3） | 全支持 |
| 资产与法务 | 零资产：自有声音事件名引用原版采样文件（引用≠再分发；静态推断，实现期验证） | 需原创音色（原版采样不可再分发进 jar） |
| 声部池（F6） | 需声部限流 | 自管 |
| 成本 | 小：映射表 + 调度 | 大：资产 + 引擎 |

**结论**：MVP 的产品承诺是「NBS 歌曲在世界里由音响播出 + 图程序控制」，A 全部满足且零资产零法务风险；B 的增益集中在全音域与自定义音色，不在 MVP 承诺内，其成本（原创采样资产 + 引擎）不成比例。A 的能力边界如实写进 §四 与产品文档。**升级到 B 的条件**：全音域保真或自定义音色成为核心诉求，或声部池实测瓶颈无法用限流缓解（届时多基准采样集优先，其次自管混音层）。
> **升级已执行（2026-10-02，plan R2）**：声部池瓶颈在高密度曲目**实测普遍丢音**（F6），按本句的阶梯启动
> **自管混音层**（多基准采样集需原创录音、法务不可行，故先做混音层）——`AudioMixer` 合成进单条 PCM 流，
> 声部消耗与音符密度无关；采样仍为运行时引用原版 16 音色（零资产零法务不变）。F1 钳制口径不变。

### 附带两条小路线的定案

| 决策 | 选定 | 弃选与原因 |
| --- | --- | --- |
| 播放调度 | **每音符服务端下发**（服务端排程 → 带目标时刻的事件包 → 客户端定点播） | 客户端本地排程器：包量更省，但要处理曲目同步/掉线补播/seek 一致性，复杂度不成比例——多音响大编制需求出现后再上 |
| 音频连线语义 | **音源引用**（连线承载「哪首曲目 + 传输状态」，图做路由/控制，编辑器做时序） | 逐音事件流（图即音序器）：留给后续「节点合成器」类玩法，MVP 不做 |

## 四、能力边界与处置 / Capability Limits

1. **音高钳制 ±1 八度**（F1）：NBS 键 33–57 外的音符被钳到窗口边缘。这与「音符盒」乐器身份一致（原版音符盒物理上也只有 24 键），但对全音域 NBS 歌曲是格式能力缺口。处置：文档声明精确窗口；播放时键值钳制到 0..24 且**保留原键数据**（不回写破坏曲目）。
2. **自定义乐器不可播**（G1）：乐器 ≥16 引用用户音色文件，A 路线无法携带。处置：导入**保留**自定义乐器段（导出不丢数据），播放降级为映射表音色 + 编辑器角标提示；发声能力属 B 路线范围。
3. **声像被世界位置取代**（G1）：NBS 的 0–200 声像面向耳机立体声；世界播放的「声像」由听者相对音响的几何位置决定（F7 衰减模型）。处置：导入保留声像数据；用多只音响的布局表达空间声像；文档写清。
4. **tick 量化网格 50 ms**：服务端 20 Hz 排程是天然网格；默认速度 10 tick/s（100 ms）无感，快速乐句（≥20 音符/s）会抖。处置：事件包携带**子 tick 目标时刻**，客户端定点播；文档声明精度口径（目标 ±1 游戏刻，子 tick 偏移尽力）。
5. **声部池静默丢音**（F6）：高密度和弦 × 多音响可能打满静态池，超出的声音无声丢失。处置：声部限流（同 tick 同音响封顶 + 近距/新事件优先）；压力用例进验证清单。
6. **大曲目同步膨胀**：曲目数据进图 NBT 后，全图同步包随曲目变大（IMAGE 像素同款账单）。处置：MVP 设曲目大小上限（阈值见计划 D8，超限拒存并提示）；Blob 分片搬运输列后续。
